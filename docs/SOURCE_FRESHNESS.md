# Source freshness workflow

Run `npm run sources:check -- --output /tmp/studyapp-source-report.json` through the supported environment proxy. The script scans every array ledger in `content/sources`, retrieves each distinct official Microsoft Learn URL, checks redirects before following them, and hashes the returned HTML with SHA256. It writes a separate report and never replaces the committed evidence baselines. A nonzero exit status means a changed source or retrieval outage needs attention; inspect the generated JSON.

Report entries distinguish unchanged HTML, changed HTML or canonical URL, unavailable retrieval, and missing hash baselines. Whole-page HTML can change because navigation or metadata changed; a hash change does not prove that an answer is wrong. Inspect the exact cited sections before deciding whether wording or answers need correction. Temporary outages preserve existing factual review and the last successful hash. A newly established baseline does not become human approval.

In Content review, import the JSON report and inspect its status summary, changed-source links and evidence notes. Explicitly applying the report checks that each baseline matches this browser before making any changes. The operation is transactional: a stale, contradictory or nonofficial entry rejects the whole report. Changed evidence pauses affected installed drafts and reviewed revisions, and affected historical snapshot revisions and adds correction warnings to historical sessions. Question wording, stored snapshots and attempt answers are preserved. Unchanged retrievals never clear a previous pause. Draft wording remains draft and receives no human review metadata; affected drafts are also paused.

Re-open the cited Learn sections, verify scenario assumptions, correct choices and every explanation, then approve the exact revision again using the existing manual confirmation. A changed answer or explanation requires a new question revision rather than editing historical snapshots. A successful retrieval or report application never automatically approves content.

The report compares committed retrieval baselines, which may differ from a browser that has already applied an earlier report. For that browser, export/use its current `sourceChecks` array as a ledger in a separate temporary directory and pass `--source-dir <directory>`. Do not overwrite authored question evidence to make a stale report apply.
